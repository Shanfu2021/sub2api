# HZZ 分支网页手动测试文档

本文档给测试人员使用。测试人员只通过网页操作，不需要改代码，不需要进服务器。

## 0. 测试环境

测试环境建议从空库开始，只保留一个管理员账号：

- 管理员邮箱：`admin@sub2api.local`
- 管理员密码：`123456`
- 访问地址：以实际部署地址为准，例如 `http://服务器IP:8080`

建议准备多个无痕窗口，分别登录管理员、一级代理、企业、普通用户、员工。所有测试账号邮箱建议带批次号，例如 `agent1-20260603@test.com`，方便搜索和截图。

每个问题按这个格式记录：

```text
用例编号：
登录账号：
页面：
操作步骤：
预期结果：
实际结果：
截图/录屏：
严重程度：
```

严重程度建议：

- P0：登录失败、页面打不开、数据丢失、核心删除逻辑错误、上游信息泄露。
- P1：归属错误、额度计算错误、分组传播错误、员工权限错误、邀请注册错误。
- P2：文案、搜索、排序、显示细节问题。

## 1. 管理员入口和侧边栏

用管理员登录。

步骤：

1. 打开首页，确认能进入后台。
2. 检查侧边栏。
3. 进入原生“用户管理”。
4. 进入“推广代理管理”。
5. 进入“购买信息”。

预期：

- 管理员能看到原生管理员功能，例如用户管理、分组管理、兑换码。
- 管理员能看到“推广代理管理”。
- 管理员能看到“购买信息”。
- 管理员不应该看到企业账号专属的“员工管理”。
- 原生“用户管理”页面没有被代理功能破坏。

## 2. 管理员创建、升级和搜索

用管理员进入“推广代理管理”。

步骤：

1. 在“直属用户管理”创建普通用户 `user-admin-1@test.com`，设置并发 `10`，RPM `100`。
2. 再创建普通用户 `user-to-agent@test.com`，升级成一级代理。
3. 再创建普通用户 `user-to-enterprise@test.com`，升级成企业。
4. 分别打开“直属用户管理”“直属代理管理”“直属企业管理”。
5. 用搜索框搜索邮箱关键字。

预期：

- 普通用户显示在“直属用户管理”。
- 升级后的一级代理显示在“直属代理管理”，不再显示在直属用户。
- 升级后的企业显示在“直属企业管理”，不再显示在直属用户。
- 管理员创建或升级出来的用户、一级代理、企业都属于管理员直属。
- 管理员不需要分配自己的额度池，设置并发/RPM 不受代理额度限制。
- 搜索框能按邮箱或用户名过滤。

## 3. 代理创建、升级和额度分配

用管理员创建一个一级代理 `agent1@test.com`，给它分配可分配池，例如并发 `20`，RPM `200`。然后用 `agent1@test.com` 登录。

步骤：

1. 确认代理侧边栏有“推广代理管理”。
2. 创建直属普通用户 `agent1-user@test.com`，分配并发 `2`，RPM `20`。
3. 创建或升级直属企业 `agent1-ent@test.com`，分配并发 `4`，RPM `40`。
4. 修改下级并发/RPM。
5. 尝试给下级分配超过代理剩余额度的并发/RPM。
6. 尝试把代理自己的额度全部分配出去。
7. 让代理自己有有限额度时，尝试给下级分配无限 RPM。

预期：

- 一级代理只能看到自己的直属用户和直属企业。
- 一级代理不能创建或升级任何代理账号。
- 代理分配给下级的是下级官方字段中的并发/RPM，同时代理自己的官方并发/RPM 应实时变为“上级给的总额减去已分配额度”。
- 上级编辑下级时看到的是“给这个下级分配的总额”，不是下级自己继续分出去后的实时剩余。
- 代理不能分配超过自己可分配池的并发/RPM。
- 代理不能把自己的并发全部分配出去，自己账号至少要能用。
- RPM 为 `0` 表示无限；但代理自己是有限 RPM 时，不能给下级分配无限 RPM。
- 代理余额只可查看，不能给普通用户直接充值。

## 4. 删除逻辑

删除逻辑必须重点测。管理员和普通代理不是一套删除规则。

### 4.1 一级代理删除自己的直属下级

用 `agent1@test.com` 登录。

步骤：

1. 删除直属普通用户 `agent1-user@test.com`。
2. 删除直属企业 `agent1-ent@test.com`。
3. 用管理员登录查看直属用户、直属企业、直属代理。

预期：

- 代理删除普通用户：用户没有真正删除，而是挂到管理员直属用户。
- 代理删除企业：企业没有真正删除，而是挂到管理员直属企业，员工不变。
- 被删除关系释放后，一级代理原来分给这些下级的并发/RPM 回收到自己的可分配额度。
- 删除确认文案只做普通提醒，不要说明“假删除”“重挂载”等内部逻辑。

### 4.2 管理员在代理管理里删除直属下级

用管理员登录，进入“推广代理管理”。

步骤：

1. 删除管理员直属普通用户。
2. 删除管理员直属企业。
3. 删除管理员直属一级代理。

预期：

- 管理员删除直属普通用户：真删除用户，并清理代理/企业/分组/倍率/邀请等扩展数据。
- 管理员删除直属企业：真删除企业和全部员工。
- 管理员删除直属一级代理：只真删除这个一级代理账号；它下面的直属普通用户、直属企业全部挂到管理员直属下。

### 4.3 管理员在原生用户管理里删除其他角色

步骤：

1. 删除普通用户。
2. 删除员工。
3. 删除企业。
4. 删除一级代理。

预期：

- 删除普通用户：真删除，并清理所有扩展数据。
- 删除员工：真删除，并从企业侧回收余额、并发、RPM。
- 删除企业：真删除企业和全部员工。
- 删除一级代理：真删除一级代理账号；它下面的用户、企业挂管理员直属。
- 删除后，任何代理管理列表中都不能再出现不存在的账号。

## 5. 兑换码

用管理员进入原生“兑换码”页面。

步骤：

1. 创建余额兑换码。
2. 创建并发兑换码。
3. 创建带有效期的兑换码。
4. 普通用户兑换余额码。
5. 代理账号兑换余额码。
6. 企业账号兑换余额码。
7. 员工账号尝试兑换。
8. 重复使用已兑换的兑换码。
9. 使用过期兑换码。

预期：

- 普通用户、代理、企业可以兑换管理员生成的兑换码。
- 兑换后余额、并发等立即更新。
- 企业兑换得到的余额可以继续分配给员工。
- 员工不能兑换，员工资源只能由企业分配。
- 已使用兑换码不能重复使用。
- 过期兑换码不能使用。
- 兑换失败提示清楚，不应误导为账号异常。

## 6. 邀请注册和返利

先确认注册和邀请码功能已开启。

步骤：

1. 管理员邀请码注册新用户。
2. 一级代理邀请码注册新用户。
3. 普通用户邀请码注册新用户。
4. 管理员直属普通用户的邀请码注册新用户。
5. 被邀请用户充值或兑换后检查返利归属。
6. 将被邀请用户从代理名下删除到管理员直属后，再充值一次。

预期：

- 管理员邀请的新用户归管理员直属。
- 一级代理邀请的新用户归一级代理直属。
- 普通用户邀请的新用户，归最近的上级代理直属。
- 如果邀请人是管理员直属普通用户，新用户归管理员直属。
- 返利仍按官方逻辑给邀请码所属用户。
- 用户直属关系后续被代理删除并转到管理员，不影响原邀请码返利归属。

## 7. 代理邀请默认配置

用一级代理 `agent1@test.com` 登录，进入代理管理里的邀请默认配置区域。

步骤：

1. 设置邀请注册默认并发为 `3`，默认 RPM 为 `30`。
2. 在“分组与倍率”里选择一个自己拥有的专属分组，设置默认传播倍率，例如 `2.4`。
3. 用 `agent1@test.com` 的邀请码注册新用户 `invite-default-user@test.com`。
4. 登录新用户检查并发、RPM、可用分组和倍率。
5. 调整代理剩余额度，让它不足以分配默认并发/RPM。
6. 再用该代理邀请码注册新用户。
7. 用管理员邀请码注册新用户，对比默认并发/RPM。

预期：

- 代理邀请码注册的新用户使用代理设置的默认并发/RPM，不使用管理员全局默认。
- 新用户自动拥有代理设置为“邀请默认传播”的专属分组。
- 新用户看到的是自己倍率，不应看到上级成本。
- 代理剩余额度不足以分配默认并发/RPM 时，注册失败，并提示上级额度不足。
- 管理员邀请码注册的新用户走管理员全局默认，不受代理默认配置影响。

## 8. 分组和倍率传播

管理员先在原生“分组管理”创建专属分组，例如 `VIP-GROUP-A`。

步骤：

1. 管理员在代理管理的“分组与倍率”里给一级代理配置专属分组和倍率。
2. 一级代理登录后查看自己的分组与倍率。
3. 一级代理给直属用户传播该分组，并设置倍率。
4. 一级代理给直属企业传播该分组，并设置倍率。
5. 企业给员工传播该分组。
6. 一级代理取消给企业的传播。
7. 用户和员工创建 API Key 时查看可选分组。

预期：

- 下级只能看到上级传播给自己的专属分组。
- 公共分组不需要传播。
- 下级看不到上级成本，只能看到自己的倍率/价格。
- 上级没有选中传播时，下级不应该拥有该专属分组。
- 上级取消传播后，该分组要连级回收，下级企业和企业员工都失去该分组。
- 用户创建 API Key 时不能看到无权限专属分组。
- 使用专属分组扣费时，按上级给自己的倍率扣费。

## 9. 企业和员工

用管理员或代理创建企业账号 `ent1@test.com`，再用企业账号登录。

步骤：

1. 企业确认侧边栏有“员工管理”，没有“推广代理管理”。
2. 企业创建员工 `emp1@test.com`。
3. 企业给员工分配余额。
4. 企业给员工分配并发和 RPM。
5. 企业给员工传播自己拥有的分组。
6. 员工登录，创建 API Key，检查可用分组。
7. 企业修改员工余额、并发、RPM。
8. 企业删除员工。
9. 管理员禁用企业账号。
10. 管理员重新启用企业账号。
11. 代理删除直属企业。
12. 管理员删除直属企业。

预期：

- 企业是一个角色账号，本质仍是用户。
- 企业只能管理员工，不能做代理管理。
- 企业不能重新定价分组，只能把自己拥有的分组传播给员工。
- 企业给员工分配余额是直接修改，不走兑换码形式。
- 企业分配给员工的余额、并发、RPM 会从企业自己可用额度扣除或回收。
- 员工不能充值、不能兑换、不能邀请返利、不能访问购买信息。
- 企业删除员工是真删除，并回收员工剩余额度和资源。
- 管理员禁用企业后，企业员工也应被禁用。
- 管理员重新启用企业后，企业员工应恢复可用。
- 代理删除直属企业不是物理删除，企业挂到管理员直属企业，员工不变。
- 管理员删除企业是真删除企业和全部员工。

## 10. 购买信息

测试“购买信息”页面，也就是下游去哪里买兑换码的信息。

### 10.1 管理员购买信息

用管理员登录。

步骤：

1. 打开“购买信息”。
2. 新增一条信息：
   - 标题：`管理员兑换码购买`
   - 链接：`https://example.com/admin-buy`
   - 联系方式：`Telegram @admin`
   - 说明：`管理员提供的兑换码购买方式`
3. 用管理员直属普通用户登录查看“购买信息”。
4. 用管理员直属一级代理登录查看“购买信息”。
5. 用管理员直属企业登录查看“购买信息”。

预期：

- 管理员管理的是全局/root 购买信息。
- 管理员直属用户、一级代理、企业看到管理员配置的信息。
- 信息标题、链接、联系方式、说明显示正确。

### 10.2 代理购买信息

用一级代理登录。

步骤：

1. 打开“购买信息”。
2. 新增一条信息：
   - 标题：`代理兑换码购买`
   - 链接：`https://example.com/agent-buy`
   - 联系方式：`Telegram @agent`
3. 用该代理直属普通用户登录查看。
4. 用该代理直属企业登录查看。
5. 用该企业员工登录检查入口。

预期：

- 代理管理的是自己传播给直属下级的购买信息。
- 代理直属普通用户、直属企业看到代理配置的信息。
- 这些下级不应看到管理员 root 信息，除非它们本来就是管理员直属。
- 员工不显示“购买信息”入口，也不能访问购买信息内容。

## 11. 上游报错脱敏

这个用例用于确认用户请求上游模型失败时，不泄露真实上游地址、域名、IP、base_url、proxy_url。

准备：

- 管理员配置一个测试渠道或上游账号，使它会稳定报错。
- 报错内容最好包含类似：
  - `https://real-upstream.example.com/v1/messages`
  - `base_url=https://real-upstream.example.com`
  - `10.1.2.3:443`

步骤：

1. 普通用户创建 API Key。
2. 用网页内可触发请求的功能，或测试工具调用该 API Key，请求会走上面故意报错的上游。
3. 查看用户侧收到的错误响应。
4. 如果是流式请求，也检查流式错误事件。
5. 管理员查看运维/错误日志。

预期：

- 用户侧错误只显示本系统自己的错误，例如 `Upstream request failed` 或脱敏后的上游错误。
- 用户侧不能出现真实上游 URL、域名、IP、base_url、proxy_url、access_token、refresh_token 等信息。
- 流式响应中也不能泄露上游地址。
- 管理员运维日志可以保留必要排错信息，但面向用户的响应必须脱敏。

## 12. 原生用户管理兼容性

用管理员进入原生“用户管理”。

步骤：

1. 创建普通用户并设置并发 `10`、RPM `100`。
2. 在“推广代理管理”的直属用户中查看该用户。
3. 登录该用户检查个人资料或可用额度。
4. 禁用该用户。
5. 再启用该用户。
6. 删除该用户。

预期：

- 原生用户管理创建的普通用户默认属于管理员直属。
- 原生设置的并发/RPM 同步显示在代理管理的直属用户列表。
- 禁用后用户不能正常使用。
- 启用后恢复。
- 删除后代理/企业/分组/倍率等扩展数据不残留。

## 13. API Key 和最终资源检查

分别登录以下角色创建 API Key：

- 普通用户
- 一级代理
- 企业账号
- 员工

预期：

- 各角色能在自己权限内创建 API Key。
- 可选分组符合上级传播结果。
- 专属分组倍率显示正确。
- 员工只能看到企业分配给自己的资源和分组。
- 没有权限的专属分组不出现在 API Key 分组选择中。

## 14. 最小回归顺序建议

如果时间有限，按这个顺序测：

1. 管理员入口和代理管理侧边栏。
2. 管理员创建一级代理、企业、普通用户。
3. 一级代理创建企业、普通用户，并确认不能创建代理。
4. 邀请注册和邀请默认配置。
5. 删除逻辑，尤其是一级代理删除用户/企业后挂管理员。
6. 企业员工分配和删除。
7. 分组传播、默认传播、回收。
8. 兑换码和企业余额分配。
9. 购买信息传播。
10. 上游报错脱敏。
