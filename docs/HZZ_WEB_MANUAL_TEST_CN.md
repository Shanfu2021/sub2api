# HZZ 网页手动测试清单

本文档用于测试 `hzz` 分支的代理、企业、邀请、兑换、删除、升级、购买信息等功能。测试人员只需要通过网页操作，不需要改代码。

## 0. 测试前准备

当前测试环境建议从空库开始，只保留一个管理员：

- 管理员邮箱：`admin@sub2api.local`
- 管理员密码：`123456`
- 访问地址：以实际部署地址为准，例如 `http://服务器IP:8080`

建议：

- 使用多个无痕窗口分别登录管理员、代理、企业、用户、员工。
- 每个阶段记录：账号、页面、操作、预期、实际结果。
- 发现问题时保留截图和账号邮箱。

## 1. 管理员基础入口

用管理员登录后检查侧边栏。

预期：

- 能看到原生管理员功能，例如用户管理、分组管理、兑换码等。
- 能看到“推广代理管理”。
- 能看到“购买信息”。
- 不应该看到企业账号专属的“员工管理”。

## 2. 管理员创建与升级下级

进入“推广代理管理”。

测试步骤：

1. 在“直属用户管理”创建普通用户 `user1@test.com`。
2. 将普通用户升级成一级代理 `agent1@test.com`，或者按页面能力创建后升级。
3. 将普通用户升级成企业账号 `ent1@test.com`，或者按页面能力创建后升级。
4. 分别进入“直属用户管理”“直属代理管理”“直属企业管理”确认账号显示在正确页面。

预期：

- 管理员创建或升级出来的用户、一级代理、企业都属于管理员直属。
- 管理员分配并发和 RPM 不受代理额度池限制。
- 搜索框可以按邮箱或用户名搜索。
- 管理员原生“用户管理”页面仍然可用。

## 3. 代理创建、升级与额度分配

用一级代理 `agent1@test.com` 登录。

测试步骤：

1. 检查侧边栏有“推广代理管理”。
2. 创建直属普通用户。
3. 创建或升级直属二级代理。
4. 创建或升级直属企业账号。
5. 给直属用户、二级代理、企业分配并发和 RPM。
6. 修改已分配的并发和 RPM。

预期：

- 代理只能看到自己的直属用户、直属代理、直属企业。
- 代理不能分配超过自己可分配额度的并发/RPM。
- 代理不能把自己的并发/RPM 全部分配出去，自己账号必须还能使用。
- 自己有限制时，不能给下级分配无限额度。
- 上级看到下级的“分配总额”用于编辑，不应该只看到下级分出去之后的实时剩余额度。
- 余额可以查看，但代理不能直接给用户充值。

## 4. 删除逻辑

删除逻辑分管理员和代理两套，必须重点测试。

### 4.1 代理删除自己的下级

用一级代理登录后执行：

1. 删除直属普通用户。
2. 删除直属企业。
3. 删除直属二级代理。

预期：

- 普通用户和企业不会被真正删除，而是变成管理员直属。
- 二级代理不会被真正删除，而是升级成一级代理并挂到管理员直属代理下。
- 被删除关系释放后，一级代理原来分给该下级的并发/RPM 要回收到自己的可分配额度。
- 页面提示不要暴露“假删除”“重挂载”等字样，只做普通删除提醒。

### 4.2 管理员在代理管理中删除直属下级

用管理员登录后执行：

1. 删除管理员直属普通用户。
2. 删除管理员直属企业。
3. 删除管理员直属一级代理。

预期：

- 删除管理员直属普通用户：真删除用户及其扩展数据。
- 删除管理员直属企业：真删除企业账号和企业员工，并清理企业相关数据。
- 删除管理员直属一级代理：只真删除这个一级代理账号；它下面的普通用户、企业、二级代理挂到管理员直属下，其中二级代理升级为一级代理。

### 4.3 管理员在原生用户管理中删除

用管理员进入原生“用户管理”执行删除。

预期：

- 删除普通用户：真删除，并清理代理、企业、分组、倍率、邀请等相关扩展数据。
- 删除员工：真删除，并从企业侧回收余额、并发、RPM。
- 删除企业：真删除企业和全部员工。
- 删除代理：真删除该代理账号，它的下级用户、代理、企业挂到管理员直属下。
- 删除后，代理管理界面不应再显示不存在的账号。

## 5. 兑换码测试

用管理员进入原生“兑换码”页面。

测试步骤：

1. 创建一个余额兑换码。
2. 创建一个并发兑换码。
3. 创建一个带有效期的兑换码。
4. 普通用户使用兑换码。
5. 代理账号使用兑换码。
6. 企业账号使用兑换码。
7. 员工账号尝试兑换。

预期：

- 普通用户、代理、企业可以兑换管理员生成的兑换码。
- 兑换后余额、并发等立即更新。
- 已使用兑换码不能重复使用。
- 过期兑换码不能使用。
- 员工不能兑换，因为员工只能由企业分配资源。
- 企业兑换得到的余额，应可继续分配给员工。

## 6. 邀请注册与返利

需要先确保注册和邀请码功能开启。

测试步骤：

1. 管理员邀请码注册新用户。
2. 一级代理邀请码注册新用户。
3. 普通用户邀请码注册新用户。
4. 被邀请用户充值或兑换后检查返利归属。
5. 代理设置邀请注册默认并发/RPM，再用该代理邀请码注册。
6. 让代理剩余额度不足，再尝试用该代理邀请码注册。

预期：

- 管理员邀请的新用户归管理员直属。
- 代理邀请的新用户归该代理直属。
- 普通用户邀请的新用户，归最近的上级代理；如果邀请人是管理员直属普通用户，则新用户归管理员直属。
- 被邀请用户后续充值产生的返利，仍按官方邀请返利逻辑给邀请码所属用户，不因直属关系后续变化而改变。
- 代理邀请码注册时使用代理自己设置的默认并发/RPM，不走管理员全局默认。
- 如果代理剩余额度不足以分配默认并发/RPM，注册应失败并提示上级额度不足。

## 7. 分组与倍率传播

管理员先在原生“分组管理”创建一个专属分组。

测试步骤：

1. 管理员在代理管理的“分组与倍率”里给一级代理配置专属分组和倍率。
2. 一级代理登录后查看自己的分组与倍率。
3. 一级代理选择是否传播该分组给直属用户、直属二级代理、直属企业。
4. 一级代理对传播给下级的分组重新定价。
5. 下级创建 API Key 时查看可选分组。
6. 上级取消传播该分组。

预期：

- 下级只能看到上级传播给自己的专属分组。
- 下级看不到上级成本，只能看到自己的倍率/价格。
- 上级没有选中传播时，下级不应该拥有该专属分组。
- 上级回收分组后，下级和下下级都应同步失去该分组。
- 用户创建 API Key 时不应看到没有权限的专属分组。

## 8. 企业与员工管理

用管理员或代理创建企业账号 `ent1@test.com`，再用企业账号登录。

测试步骤：

1. 企业创建员工账号。
2. 企业给员工分配余额。
3. 企业给员工分配并发和 RPM。
4. 企业给员工传播自己拥有的分组。
5. 员工登录后创建 API Key 并查看可用分组。
6. 企业修改员工余额、并发、RPM。
7. 企业删除员工。
8. 管理员禁用企业账号。
9. 管理员重新启用企业账号。
10. 管理员删除企业账号。

预期：

- 企业是一个角色账号，本质仍是用户，但有“员工管理”侧边栏。
- 企业不能做代理管理。
- 企业不能重新定价分组，只能把自己拥有的分组传播给员工。
- 企业给员工分配余额是直接修改，不走兑换码形式。
- 企业分配给员工的余额、并发、RPM 会从企业自己可用额度中扣除或回收。
- 员工不能充值、不能兑换、不能邀请返利、不能访问购买信息。
- 企业删除员工是真删除，并回收员工剩余额度和资源。
- 管理员禁用企业后，企业员工也应被禁用。
- 管理员重新启用企业后，企业员工应恢复可用。
- 管理员删除企业是真删除企业和全部员工。
- 代理删除直属企业不是物理删除，企业应挂到管理员直属企业下，企业员工不变。

## 9. 购买信息传播

测试“购买信息”页面。

管理员测试：

1. 管理员打开“购买信息”。
2. 新增一条购买信息，例如：
   - 标题：管理员兑换码购买
   - 链接：`https://example.com/admin-buy`
   - 联系方式：`Telegram @admin`
   - 说明：管理员提供的兑换码购买方式
3. 普通用户、一级代理、企业登录后查看“购买信息”。

代理测试：

1. 一级代理打开“购买信息”。
2. 新增一条代理自己的购买信息。
3. 该代理直属普通用户、直属企业、直属二级代理登录查看“购买信息”。
4. 员工登录检查入口。

预期：

- 管理员管理的是全局/root 购买信息。
- 管理员直属用户、一级代理、企业看到管理员配置的信息。
- 代理管理的是自己传播给直属下级的信息。
- 代理直属下级看到该代理配置的信息。
- 员工不显示“购买信息”入口，也不能访问购买信息 API。

## 10. 原生用户管理兼容性

管理员进入原生“用户管理”页面。

测试步骤：

1. 创建普通用户并设置并发/RPM。
2. 登录该用户检查个人资料中的并发/RPM。
3. 禁用该用户。
4. 再启用该用户。
5. 删除该用户。

预期：

- 原生创建的用户默认属于管理员直属。
- 原生设置的并发/RPM 应同步显示到代理管理的直属用户列表。
- 禁用后用户不能正常使用。
- 启用后恢复。
- 删除后代理/企业扩展表中不应残留该用户。

## 11. API Key 与分组最终检查

分别登录以下角色，创建 API Key：

- 普通用户
- 一级代理
- 二级代理
- 企业账号
- 员工

预期：

- 各角色能创建 API Key。
- 可选分组符合上级传播结果。
- 专属分组倍率显示正确。
- 员工只能看到企业分配给自己的资源和分组。
- 没有权限的专属分组不应出现在 API Key 分组选择中。

## 12. 测试完成记录模板

每个问题按这个格式记录：

```text
测试阶段：
登录账号：
页面路径：
操作步骤：
预期结果：
实际结果：
截图/录屏：
备注：
```

优先级建议：

- P0：登录失败、页面打不开、数据清空、核心删除逻辑错误。
- P1：归属错误、额度计算错误、分组传播/回收错误、员工权限错误。
- P2：提示文案不清楚、搜索/排序显示问题。
